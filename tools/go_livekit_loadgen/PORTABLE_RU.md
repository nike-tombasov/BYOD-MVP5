# BYOD Loadgen Portable Win64 — инструкция

## Что это

Это автономный Windows-пакет `byod-loadgen.exe` для нагрузочных BYOD VPS-проверок. На вспомогательных Windows-машинах Go не нужен: достаточно распаковать архив, отредактировать `.bat` файл и запустить его. Логи каждого запуска пишутся в папку `out\...` внутри распакованного пакета.

## Как отредактировать и запустить `.bat`

1. Откройте нужный `run_*.bat` в редакторе.
2. Вверху файла задайте:
   - `SERVER` — адрес BYOD VPS, например `http://161.104.18.27`.
   - `RUNNER_ID` — уникальное имя этой машины, например `win1`, `win2`.
   - `LOADGEN_KEY` — ключ loadgen, выданный оператором.
   - `START_AT` — `now` для немедленного старта или точное RFC3339-время, например `2026-06-22T22:30:00+03:00`.
3. Запустите `.bat` из PowerShell или cmd.
4. После теста заархивируйте и отправьте оператору папку `out\<run>`.

## Справочник флагов

### Основные

- `-server` — URL BYOD сервера. Безопасное значение: адрес тестового VPS. Меняйте для другого стенда. Пример: `-server http://161.104.18.27`.
- `-profile` — профиль окружения: обычно `vps-nginx`. Безопасно оставлять `vps-nginx` для VPS.
- `-mode` — тип проверки: `backend-ws-only`, `livekit-connect-only`, `livekit-subscribe-discard-rtp`. Меняйте только по сценарию A/B/C.
- `-listeners` — число воркеров-слушателей. Безопасно начинать с 30–50. Увеличивайте только по команде оператора.
- `-required-listeners` — сколько слушателей нужно для успешного HOLD; по умолчанию равно `-listeners`. Меняйте только для частичных проверок.
- `-exact-target` — требует полный target для официального proof; безопасное значение `true`.
- `-runner-id` — уникальный ID машины/запуска. Меняйте на каждой машине, например `win1-b50`.
- `-out-dir` — папка логов. Безопасно `out\<run>`.
- `-loadgen-key` — ключ доступа loadgen. Меняйте на значение, выданное оператором.

### Старт и форма запуска

- `-start-at` — когда начинать запуск воркеров: `now` или RFC3339 timestamp. Безопасное значение `now`. Для синхронного старта нескольких машин задайте одно будущее время. Пример: `-start-at 2026-06-22T22:30:00+03:00`.
- `-start-mode` — форма запуска после наступления `start-at`: `ramp` или `burst`. Безопасно `burst` для коротких A/B/C примеров, `ramp` для плавного запуска.
- `-burst-size` — сколько воркеров запускать за один burst. Для немедленного B50 используйте `50`; для B100 синхронно можно `50`.
- `-burst-interval-ms` — пауза между burst, миллисекунды. `0` запускает burst без паузы; `1000` делает паузу 1 секунду.
- `-ramp-per-sec` — скорость ramp, воркеров в секунду. Используется только при `-start-mode ramp`. Пример: `-ramp-per-sec 20`.

### Тайминги

- `-hold-sec` — сколько секунд держать достигнутую цель. Безопасно `45` или `60`.
- `-target-wait-sec` — сколько ждать выхода на цель после запуска воркеров. Безопасно `20`–`30`.
- `-backend-connect-timeout-sec` — timeout подключения/первого backend-сообщения. Безопасно `10`.

### Gate C

- `-subscribe-mode` — режим подписки для `livekit-subscribe-discard-rtp`: `selected` подписывается на выбранный канал воркера, `all` подписывается шире. Безопасно `selected`.
- `-channel-mode` — если поддерживается вашей сборкой, задает схему выбора канала. Оставляйте значение по умолчанию, если оператор не просит иначе.
- `-channel-id` — если поддерживается вашей сборкой, фиксирует конкретный канал. Обычно не нужен для portable A/B/C.

Ограничение: если на выбранном канале опубликовано несколько audio tracks с одинаковым `track_name`, текущая portable-инструкция не включает дополнительный лимит подписок; проверьте summary на `unexpected_extra_audio_tracks`.

## Минимальные примеры

### A50 backend burst now

Запустите `run_a50_backend_now.bat` с `START_AT=now`.

### B50 LiveKit burst now

Запустите `run_b50_livekit_now.bat` с `START_AT=now`.

### C30 selected RTP now

Запустите `run_c30_rtp_selected_now.bat` с `START_AT=now`.

### Синхронный B100 в фиксированное время

На всех машинах укажите одинаковый `START_AT=2026-06-22T22:30:00+03:00`, разные `RUNNER_ID`, затем запустите `run_b100_livekit_at_time.bat` заранее.

## Что отправить обратно

Отправьте из папки `out\<run>`:

- `summary_*.json`;
- `events_*.jsonl`;
- по возможности команду запуска или screenshot окна команды.
